# 里程碑与待决事项

## 第一期里程碑

设计系统前置，功能按体验价值排序；服务端开发与前端并行，节奏跟着前端的需求走。

| 阶段 | 内容 | 预估 |
|---|---|---|
| M0 | **视觉原型**：只有白板和便利贴的单页（拖拽、配色、动效），先把手感调到满意（✅ 已完成） | 3–5 天 |
| M1 | 设计 token、基础组件（Storybook）、注册登录页；服务端脚手架、OpenAPI、数据库迁移、认证（✅ 已完成；改密码、设备管理的接口已就绪，页面在 M4 做） | 1 周 |
| M2 | **白板 + 便利贴**：双击新建、拖拽、颜色、原地编辑、动效；Tiptap 编辑器；本地优先 + 登录后按条比新旧的同步（✅ 已完成；用同步接口代替了单独的 CRUD 接口） | 1–2 周 |
| P0 | **抽出共享包**：npm workspaces；`packages/core` 包含 API 类型与客户端、登录会话、同步合并规则与引擎、存储接口与保存队列、正文工具、设计 token；Web 改为依赖它，行为不变（✅ 已完成） | 2–3 天 |
| M3 | **快速记录**：全局输入框、自然语言解析、命令面板、快捷键（✅ 已完成；待办存为便利贴里的待办项，时间、优先级、标签写在待办项属性里，M4 的待办视图从便利贴里汇总） | 1–2 周 |
| M4 | 待办视图（今天、即将、已完成）、看板与标签、撤销系统、空状态、搜索（✅ 已完成：看板随同步接口一起同步，删除看板连同便利贴、可撤销；待办视图和标签从便利贴里汇总；命令面板搜索所有看板；另补上 M1 留下的“账号与设备”页；随后补齐看板拖拽排序和白板 / 列表视图切换） | 1–2 周 |
| M5 | WebSocket 实时更新、性能打磨、回收站（✅ 已完成：实时通知目前单实例，多实例时换 Redis；回收站在本机保留 30 天，服务端定期清理；首屏代码减半，500 张便利贴操作不卡。此前已提前完成：离线同步、IndexedDB、暗色模式、Docker 部署与每日数据库备份） | 1–2 周 |
